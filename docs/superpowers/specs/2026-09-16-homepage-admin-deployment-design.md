# 首页、后台与双平台发布优化设计

日期：2026-09-16

## 目标

以 HIROL Lab 首页的清晰学术站结构为参考，重做本站首页首屏与信息层级，同时保留本站已有的 Astro 静态前端、Django 内容后台和 PostgreSQL 图片存储方案。所有首页业务内容均可由后台维护；保存后可触发 Vercel 重建，GitHub Pages 则继续作为 Markdown 内容的静态镜像。

本轮同时改善移动端体验、首屏性能、SEO 和两套发布链路，但不改变现有成员、科研平台、成果、新闻详情页的数据结构与公开 URL。

## 首页信息架构

首页按以下顺序组成：

1. 固定式主导航：品牌标识、首页、团队成员、科研平台、科研成果、加入我们。
2. 单张沉浸式首屏：横向团队或实验室图片、所属单位、实验室中英文名称、简短介绍与可选行动按钮。
3. 实验室简介：由站点设置中的简介与团队合照驱动。
4. 实验室最新动态：展示后台已发布新闻中最新的若干条，可进入新闻详情或全部动态页。
5. 联系与加入提示：复用后台招生开关、招生标题、说明和邮箱。
6. 现有全站页脚。

首页不再展示研究方向矩阵和代表性成果矩阵；这些内容继续保留在各自独立页面。新闻详情和 `/news` 页面仍保留，虽然不放入主导航。

## 视觉设计

参考 HIROL Lab 的蓝白学术气质与大图首屏，但不逐像素复制。

- 主色：学院蓝 `#174A8B`；深蓝 `#0C2F59`；正文墨色 `#172033`；背景白 `#FFFFFF`；浅灰蓝 `#EEF3F8`；强调金 `#C89B3C`。
- 字体：中文使用系统可用的现代黑体序列，英文与数字使用相同的无衬线体系，避免额外字体下载影响首屏。
- 首屏：图片承担主要视觉记忆点，覆盖克制的深蓝渐变以保证文字对比度；不保留装饰圆环和轮播控件。
- 内容区：减少大圆角、浮夸阴影和重复标签，用留白、细分隔线和图片比例建立层级。
- 动效：仅保留导航状态、菜单开合和可交互元素反馈；尊重 `prefers-reduced-motion`。

## 响应式行为

- 桌面端主导航保持单行，五个主要栏目按用户指定顺序排列。
- 中小屏隐藏桌面导航，改为可键盘操作的菜单按钮和抽屉式菜单，避免文字压缩或横向溢出。
- 首屏桌面使用宽幅裁切，手机使用更高的安全画幅，并确保后台上传图片在 `object-fit: cover` 下不遮挡核心文字。
- 最新动态在桌面为多列，在手机为单列；触控目标不小于 44px。
- 所有布局在 320px、390px、768px、1024px 和 1440px 宽度下无水平滚动。

## 后台与数据流

首页内容仍通过统一的 `/api/content/` 数据包构建：

`Django Admin 保存 → PostgreSQL / MediaFile → /api/content/ → Vercel 构建 Astro → 静态首页`

具体映射：

- 首屏主图与文字：使用“首页轮播”中排序第一且已发布的记录。后台界面会明确说明首页采用第一条；若没有记录，则回退到站点设置中的团队合照与实验室名称。
- 实验室简介与团队合照：使用“站点设置”的名称、英文名、所属单位、简介和首页团队合照。
- 最新动态：使用“科研新闻”中已发布记录，按置顶和日期排序；显示条数继续由首页文案设置控制。
- 加入我们：使用站点设置中的招生开关、标题、说明与邮箱。
- 导航：默认值改为首页、团队成员、科研平台、科研成果、加入我们；管理员自定义导航时继续尊重后台配置。

图片上传沿用数据库二进制存储和 `/api/media/<hash>` 内容哈希 URL。上传时校验类型、体积和像素，前端输出明确的宽高或固定比例容器，防止布局偏移。

## 发布可靠性

Vercel 是带后台的正式站点。后台保存内容后：

1. 数据库事务成功后才发出重建请求。
2. 已配置 Deploy Hook 时优先使用 Hook；否则使用 Vercel API 配置。
3. 后台明确显示发布服务是否已配置，并在手动触发时展示接受或失败信息。
4. 测试覆盖保存触发、关闭自动重建、不触发草稿泄漏、上传图片可访问和接口序列化。

GitHub Pages 是纯静态镜像。`publish:pages` 继续使用仓库 Markdown 数据、`/lab-website` 基础路径和 `gh-pages` 分支，不提供 Django 后台。两套构建都必须通过站内链接、SEO 元数据和图片替代文本自检。

## 性能与 SEO

- 首屏只加载一张关键图，移除首页轮播脚本和定时器；关键图使用高优先级，其余图片懒加载。
- 为首屏和新闻图片输出合理的 `sizes`、尺寸约束与解码策略；后台上传继续压缩超大图片。
- 首页保留唯一 `h1`、规范 canonical、Open Graph、Twitter Card、站点结构化数据、sitemap 与 robots。
- 首页描述来自后台“搜索引擎简介”，为空时回退到一句话简介。
- 保持 GitHub Pages 子路径下的 canonical、资源 URL、RSS、sitemap 和站内链接正确。

## 错误与空状态

- 未上传首屏图片时显示品牌色背景，不出现破图。
- 没有新闻时显示后台可编辑的空状态文案。
- 图片接口不可用时保留卡片结构与文字内容。
- 明确配置 `API_BASE` 后接口失败继续阻止正式构建，避免示例内容覆盖线上数据。
- Vercel 发布服务未配置时后台禁止误报“已发布”，并给出具体配置提示。

## 验收与测试

实施完成后执行：

- `npm test`
- `npm run build`
- `npm run verify:dist`
- `.venv/Scripts/python.exe api/manage.py test core --settings=labbackend.test_settings`
- 使用桌面与 390px 手机视口检查首页、菜单、图片裁切、暗色主题和键盘操作。
- 使用 `BASE_PATH=/lab-website` 构建并运行产物自检，验证 GitHub Pages 子路径。
- 推送 `main` 后确认 Vercel 正式部署状态；发布 `gh-pages` 后确认 Pages URL 可访问。

## 不在本轮范围

- 不新增实时前端 CMS 预览。
- 不让 GitHub Pages 运行 Django 后台。
- 不替用户生成真实实验室图片、成员资料或科研成果内容。
- 不迁移现有 PostgreSQL 图片到第三方对象存储。
